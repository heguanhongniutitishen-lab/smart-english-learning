## 已实现的验收场景

- [x] 真实学生读取当天计划、已审核发布的学习题目；真实答题由 API 判分，产生唯一作答记录。

- [x] 浏览器端 / API 的自动化用例覆盖权限边界、证据关联、重试、错误反馈和学习主线返回。

## 安全发布阻塞门槛

- 当前 API 只依赖客户端可伪造的 `x-user-id` 与学生绑定查询，不是可信的身份认证；不能接入真实学生资料。
- 学生联调页面会明确显示身份不安全的测试模式提示。
- `npm run check:release --workspace=@sel/student-web` **必须非零退出**，明确禁止当前版本进入正式交付；CI 使用 `npm run test:release-gate --workspace=@sel/student-web` 验证这一阻塞条件保持生效。此检查是代码特征扫描而不是安全审计，后续即便扫描条件消失也必须有真实服务端令牌验证、安全测试和人工审查，才可讨论发布。
- 本阶段不改变学习引擎 S0–S4，也不自动判定错因或生成正式修复任务。

## 学生 API 签名身份校验基础

- 默认 `STUDENT_AUTH_MODE=development` 保留 CI/本地受控联调。`NODE_ENV=production` 下禁止此模式，启动即拒绝。
- 配置 `STUDENT_AUTH_MODE=signed` 时，必须设置长度至少 32 字节的 `STUDENT_AUTH_SECRET`。学生 API 仅接受短效、HMAC-SHA256 签名的 Bearer 身份声明；即使请求携带任意 `x-user-id`，也以签名令牌中的用户 ID 为准，再由数据库学生绑定关系判断资源归属。
- `POST /api/v1/auth/wechat/login` 的 `open_id` 自报方式在严格模式中被禁用。尚未实现真实微信 code 交换与可信签发，生产环境不得将开发联调模式作为登录。
- 当前签名令牌为验证基础，**不是完整正式认证方案**：还需要正式身份提供方、发行流程、密钥托管与轮换、浏览器安全会话管理、退出与撤销、限流及安全测试。
